## 🏗️ 最终架构

### 分层架构（符合 DDD 原则）

```
com.contract/
├── adapter/                          # 适配层（接口适配）
│   ├── controller/                   # REST API
│   │   ├── TemplateController.java
│   │   └── TemplateVersionController.java
│   └── persistence/                  # 持久化适配
│       ├── entity/                   # 数据库实体
│       └── mapper/                   # MyBatis Mapper
│
├── application/                      # 应用服务层（用例编排）
│   └── template/
│       ├── TemplateService.java
│       └── TemplateVersionService.java
│
├── domain/                           # 领域层（核心业务）
│   └── template/
│       ├── repository/               # 仓储接口（领域定义）
│       │   ├── TemplateRepository.java
│       │   └── TemplateVersionRepository.java
│       ├── Template.java             # 领域模型（充血模型）
│       └── TemplateVersion.java
│
├── infrastructure/                   # 基础设施层（技术实现）
│   ├── id/                           # ID 生成
│   │   └── SnowflakeIdGenerator.java
│   └── persistence/
│       └── repository/               # 仓储实现（基础设施实现）
│           ├── TemplateRepositoryImpl.java
│           └── TemplateVersionRepositoryImpl.java
│
└── common/                           # 公共模块
    ├── enums/                        # 枚举定义
    ├── exception/                    # 异常体系
    └── result/                       # 统一响应
```

### 依赖关系（符合依赖倒置原则）

```
Controller → Service → Repository Interface（领域层）
                            ↑
                    Repository Impl（基础设施层）
                            ↓
                          Mapper
```

**关键点**：
- Service 层依赖领域层的仓储接口，不依赖基础设施实现
- Repository 接口在领域层定义，在基础设施层实现
- Entity ↔ Domain 转换封装在仓储实现中

## 📝 命名规范（Google 风格）

### 包命名
- ✅ 全小写，点分隔：`com.contract.domain.template.repository`
- ✅ 避免驼峰：`template.repository` 而非 `templateRepository`

### 类命名
- ✅ 大驼峰：`TemplateRepository`, `TemplateRepositoryImpl`
- ✅ 接口不加 I 前缀，实现类加 Impl 后缀

### 方法命名
- ✅ 小驼峰，动词开头：`findById`, `findByTemplateCode`, `save`, `update`
- ✅ 布尔返回值用 `is/has/can` 开头：`isEnabled`, `hasPermission`

### 常量命名
- ✅ 大写下划线：`MAX_VERSION_COUNT`, `DEFAULT_PAGE_SIZE`

### 数据库字段
- ✅ 下划线命名：`created_by`, `created_at`, `updated_by`, `updated_at`
- ✅ MyBatis 自动映射到驼峰：`createdBy`, `createdAt`

## 🎯 关键设计决策

### 1. 充血模型 vs 贫血模型
**决策**：采用充血模型
- 领域模型包含业务方法：`create()`, `publish()`, `disable()`
- 业务逻辑封装在领域对象中
- Service 层编排用例，不包含核心业务逻辑

### 2. 仓储模式
**决策**：严格遵循 DDD 仓储模式
- Repository 接口定义在领域层
- Repository 实现在基础设施层
- Service 层依赖接口，不依赖实现

### 3. 命名规范
**决策**：采用 Google 风格
- 包名：全小写点分隔
- 类名：大驼峰
- 方法名：小驼峰，动词开头
- 数据库字段：下划线，自动映射到驼峰

### 4. 测试策略
**决策**：TDD + 单元测试
- 先写测试，再实现
- 使用 H2 内存数据库
- 测试覆盖核心业务场景

### 5. 前端技术选型
**决策**：原生技术栈
- 不依赖前端框架
- 使用最新 Web 标准（ES6+, CSS Grid）
- 便于后端开发人员理解和维护
