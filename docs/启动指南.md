### 方式 1：手动安装 Maven（推荐）

**步骤 1：安装 Maven**

```bash

export PATH=$PATH:~/.local/bin/apache-maven-3.9.6/bin
```


## 🌐 前端访问说明

### HTML 文件位置

所有前端文件已集成到 Spring Boot 静态资源目录：

```
src/main/resources/static/
├── index.html          # 入口页面
├── simple.html         # 简单界面
├── complex.html        # 复杂界面
├── css/
│   └── style.css
└── js/
    ├── api.js
    └── contract-api.js
```

### 为什么不需要 Node.js？

**原因**：我们使用的是**原生 JavaScript（ES6+）**

- ✅ JavaScript 代码直接写在 `<script>` 标签内
- ✅ 使用浏览器内置的 Fetch API 调用后端接口
- ✅ 不依赖任何前端框架（React、Vue 等）
- ✅ 不需要构建工具（Webpack、Vite 等）
- ✅ 不需要 Node.js 运行时

**技术栈**：
- HTML5 + CSS3 + JavaScript ES6+
- Fetch API（浏览器原生支持）
- CSS Grid & Flexbox（现代浏览器原生支持）
- ES6 模块化（浏览器原生支持）

### 前端如何工作？

**工作流程**：

1. **静态文件服务**：Spring Boot 自动提供静态文件服务
   - 访问 http://localhost:8080/index.html
   - Spring Boot 返回静态 HTML 文件

2. **浏览器解析**：
   - 浏览器解析 HTML 结构
   - 加载 CSS 样式文件
   - 执行 JavaScript 代码

3. **API 调用**：
   ```javascript
   // JavaScript 使用 Fetch API 调用后端
   const response = await fetch('/api/templates', {
       method: 'POST',
       headers: {'Content-Type': 'application/json'},
       body: JSON.stringify(data)
   });
   ```

4. **数据渲染**：
   - JavaScript 接收后端返回的 JSON 数据
   - 动态更新 DOM 元素
   - 显示在页面上

### 为什么集成到 Spring Boot？

**问题**：如果用浏览器直接打开 HTML 文件（`file://` 协议）：

```text
❌ CORS 错误：跨域请求被阻止
❌ 无法调用后端 API：http://localhost:8080/api/templates
❌ Fetch API 报错：Cross-Origin Request Blocked
```

**解决方案**：集成到 Spring Boot 静态资源目录：

```text
✅ 同源策略：前端和后端都是 http://localhost:8080
✅ CORS 正常：允许调用后端 API
✅ 一键启动：前端和后端一起启动
```

## 🐛 常见问题

### 问题 1：Maven 找不到

**解决方案**：
```bash
# 安装 Maven
sudo apt-get install -y maven
```

### 问题 2：端口 8080 被占用

**解决方案**：
```bash
# 查找占用进程
lsof -i :8080

# 杀掉进程
kill -9 <PID>

# 或者修改端口
# 在 application.yml 中修改：
server:
  port: 9090
```

### 问题 3：H2 数据库连接失败

**解决方案**：
```bash
# 检查 H2 Console
访问 http://localhost:8080/h2-console

# JDBC URL: jdbc:h2:mem:testdb
# User: sa
# Password: (空)
```

### 问题 4：前端页面无法访问

**解决方案**：
```bash
# 检查静态资源目录
ls -la src/main/resources/static/

# 如果文件不存在，重新创建
```

### 问题 5：CORS 错误

**解决方案**：
确保前端文件在 Spring Boot 静态资源目录中，而不是用 `file://` 协议直接打开。
